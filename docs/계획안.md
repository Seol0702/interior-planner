# 3D 인테리어 플래너 프로젝트 계획안

> 실측 평면도 기반으로 집을 구성하고, KiCad처럼 가구 라이브러리에서 부품을 꺼내 배치하는 웹 3D 인테리어 도구

- **작성일**: 2026-11-16
- **목적**: 개인 사용 + GitHub 포트폴리오
- **플랫폼**: 웹 (필요 시 추후 Tauri로 데스크톱 앱화)
- **개발자 수준**: 프로그래밍 초급, 3D 경험 없음 → 학습하면서 진행

---

## 1. 프로젝트 개요

### 1.1 핵심 아이디어
1. 실제 매물의 면적·평면도를 불러오거나 직접 입력해서 **정확한 치수의 집**을 만든다.
2. 전자회로 CAD인 KiCad에서 부품을 꺼내 배치하듯, **가구 라이브러리에서 가구를 골라 배치**한다.
3. 2D 평면도와 3D 화면을 **동시에 보면서** 직관적으로 꾸민다.

### 1.2 차별점
- **실측 기반**: 공공데이터(건축물대장) 면적으로 도면 정확도를 검증
- **배치 규칙 검사**: KiCad의 DRC(설계 규칙 검사)를 응용해 통로 폭, 문 열림 반경 충돌 등을 자동 경고
- **BOM(가구 목록) 자동 집계**: 배치한 가구의 목록과 총예산을 자동 계산

## 2. 데이터 수집 전략

### 2.1 데이터 출처별 현실 점검

| 출처 | 얻을 수 있는 것 | 제약 | 사용 여부 |
|---|---|---|---|
| **국토교통부 건축HUB 건축물대장 API** (공공데이터포털) | 전유면적, 공용면적, 층별개요, 주용도 등 **숫자 정보** | 벽 위치·방 치수 같은 **형상 정보는 없음** | ✅ 사용 (면적 자동입력·검증용) |
| **세움터 평면도(건축물현황도)** | 실제 도면 PDF | 소유자 동의 또는 정해진 경우에만 발급, API 자동화 불가 | △ 사용자가 직접 받아서 업로드 |
| **네이버 부동산** | 단지 평면도 이미지, 매물 정보 | **공식 API 없음**, 크롤링 시 약관·법적 분쟁 위험 | ❌ 자동 수집 안 함 (사용자 캡처 업로드만) |

### 2.2 3단 입력 방식 (결론)
1. **주소 검색 → 건축HUB API**
   전용면적 등 기본 정보를 자동으로 채우고, 사용자가 그린 도면의 면적과 비교해 오차를 알려줌.
2. **평면도 이미지 업로드 → 트레이싱**
   사용자가 네이버 부동산 캡처나 세움터 PDF를 업로드하고, 기준이 되는 한 변의 실제 길이(예: 거실 폭 3,600mm)를 입력하면 축척이 자동 보정됨. 그 위에 벽을 따라 그림.
3. **완전 수동 입력**
   줄자로 잰 치수로 벽을 직접 그림.

> 추후 확장: 평면도 이미지 AI 인식으로 벽 자동 추출

## 3. 핵심 기능 설계 (KiCad 개념 매핑)

| KiCad | 이 프로그램 |
|---|---|
| 심볼 + 풋프린트 + 3D 모델 | **가구 = 2D 평면 외곽 + 3D 모델(glTF) + 메타데이터**(W×D×H, 브랜드, 가격, 구매 링크) |
| 라이브러리 브라우저, `A`키로 배치 | 가구 라이브러리 패널, 검색, 단축키 배치, `R`키 회전 |
| 그리드 스냅 | 10mm 그리드 스냅, 벽에 붙이기 |
| DRC (설계 규칙 검사) | **배치 규칙 검사**: 통로 폭 부족, 문·서랍 열림 반경 충돌, 창문·콘센트 가림 |
| BOM (부품 목록) | **가구 목록 + 총예산 자동 집계** |
| 사용자 라이브러리 | 내 가구를 실측해서 등록, **파라메트릭 가구**(폭 등을 숫자로 바꾸면 모양이 따라 바뀜) |

### 3.1 데이터 모델 (초안)
```
Project (프로젝트)
└── Floor (층)
    ├── Wall (벽: 중심선 시작점·끝점 + 두께 + 높이)
    ├── Opening (문·창문: 어느 벽의 어느 위치, 폭·높이)
    ├── Room (방: 벽으로 둘러싸인 영역, 면적 자동 계산)
    └── FurnitureInstance (배치된 가구: 라이브러리 ID + 위치 x,y + 회전)

FurnitureLibraryItem (가구 라이브러리 항목)
├── 이름, 카테고리
├── 치수 W × D × H (mm)
├── 2D 외곽 형태
├── 3D 모델 (.glb) 또는 기본 박스
└── 브랜드, 가격, 구매 링크 (선택)
```

저장 형식은 **JSON**. 예시:
```json
{ "가구": "소파", "폭": 2100, "깊이": 900, "x": 1500, "y": 300, "회전": 90 }
```

## 4. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | **TypeScript** | 하나의 언어로 전부 해결, 타입 검사로 초보자 실수 방지 |
| 화면 구성 | **React** | 화면을 블록(컴포넌트) 단위로 조립 |
| 3D | **react-three-fiber + drei** (Three.js 기반) | Three.js를 React 방식으로 쉽게 사용, 카메라 조작·그리드 등 기성 부품 제공 |
| 2D 편집 | Canvas 기반 (Konva 등) | 평면도 그리기·드래그 |
| 3D 모델 형식 | **glTF (.glb)** | 웹 3D 표준 형식 |
| 저장 | 브라우저 저장소 + JSON 내보내기/불러오기 | 서버 없이 시작 가능 |
| API 키 보호 | **Vercel 서버리스 함수** | 공공데이터 API 키를 화면 코드에 노출하지 않음 |
| 배포 | **Vercel** (또는 GitHub Pages) | 무료, GitHub와 연동해 자동 배포 |
| 코드 관리 | **Git + GitHub** | 버전 관리 + 포트폴리오 공개 |
| (추후) 데스크톱 | Tauri | 같은 웹 코드를 설치형 앱으로 포장, 용량이 작음 |

### 4.1 웹을 선택한 이유
- 포트폴리오에서 **"링크 클릭 → 바로 체험"**이 가장 강력한 어필 포인트
- 설치·OS별 빌드·코드 서명 문제가 없음
- Electron/Tauri 앱도 내부는 웹 기술이므로, 나중에 그대로 앱으로 포장 가능 (손해 없음)
- 배워야 할 기술 수가 가장 적음

## 5. 단계별 로드맵

### 0단계: 개발 환경 세팅
- [ ] Node.js 설치 (TypeScript 실행 엔진)
- [ ] VS Code 설치 (코드 편집기)
- [ ] Git 설치 + GitHub 계정 생성
- [ ] 프로젝트 생성 (Vite + React + TypeScript 템플릿)
- [ ] **목표: 브라우저에 회색 3D 박스 하나 띄우기**

### 1단계: MVP (최소 기능 제품)
> 핵심 가치를 보여줄 수 있는 가장 작은 버전
- [ ] 직사각형 방 하나 만들기 (가로·세로·높이 입력)
- [ ] 박스 형태 기본 가구 몇 종(소파, 침대, 책상, 옷장 등) 배치
- [ ] 드래그로 이동, `R`키로 회전, 그리드 스냅
- [ ] 마우스로 3D 화면 돌려보기
- [ ] JSON 저장/불러오기
- [ ] Vercel 배포 → **첫 라이브 데모 링크 확보**

### 2단계: 실측 도면
- [ ] 2D 평면도 편집기: 벽을 선으로 그리기 (다각형 방 지원)
- [ ] 문·창문 배치
- [ ] 평면도 이미지 업로드 + 축척 보정 + 트레이싱
- [ ] 건축HUB API 연동 (서버리스 함수로 키 보호) → 전용면적 자동입력·면적 검증
- [ ] 2D ↔ 3D 동시 보기

### 3단계: KiCad식 라이브러리 & 검사
- [ ] 가구 라이브러리 브라우저 (카테고리·검색)
- [ ] glTF 3D 모델 불러오기 (라이선스 확인된 CC0 모델 위주)
- [ ] 사용자 가구 등록 (실측 치수 입력)
- [ ] 파라메트릭 가구
- [ ] **배치 규칙 검사** (통로 폭, 열림 반경 충돌)
- [ ] **BOM / 예산 집계**

### 4단계: 확장
- [ ] 평면도 이미지 AI 자동 인식
- [ ] 바닥재·벽지 재질 변경
- [ ] 공유 링크
- [ ] (선택) Tauri로 데스크톱 앱 패키징

## 8. 용어 정리

| 용어 | 설명 |
|---|---|
| **프론트엔드** | 사용자가 보고 만지는 화면 부분 (식당의 홀) |
| **백엔드** | 화면 뒤에서 일하는 서버 (식당의 주방) |
| **API** | 프로그램끼리 데이터를 주고받는 약속된 창구 |
| **API 키** | API를 쓸 수 있는 회원증, 숨겨야 함 |
| **프록시 / 서버리스 함수** | API 키를 숨긴 채 대신 요청해 주는 중간 심부름꾼. 서버 관리 없이 호출될 때만 실행 |
| **TypeScript** | JavaScript에 타입 표시를 더한 언어, 실수를 미리 잡아줌 |
| **React** | 화면을 레고 블록(컴포넌트)처럼 조립하는 도구 |
| **JSON** | 사람과 프로그램 모두 읽을 수 있는 데이터 기록 형식 |
| **Three.js** | 웹 브라우저에서 3D를 그리는 대표 라이브러리 |
| **react-three-fiber (R3F)** | Three.js를 React 방식으로 쓰게 해주는 도구 |
| **drei** | R3F용 편의 부품 모음 (카메라 조작, 그리드, 모델 로딩 등) |
| **glTF (.glb)** | 웹 3D 모델 표준 파일 형식 ("3D계의 JPG") |
| **파라메트릭 가구** | 숫자(치수)를 바꾸면 모양이 자동으로 바뀌는 가구 |
| **배포** | 만든 프로그램을 인터넷에 올려 링크로 접속 가능하게 하는 것 |
| **GitHub / GitHub Pages** | 코드 저장·기록 서비스 / 그 코드를 무료 웹사이트로 띄우는 기능 |
| **Vercel** | 무료 배포 서비스, 서버리스 함수도 함께 올릴 수 있음 |
| **Electron / Tauri** | 웹 프로그램을 설치형 데스크톱 앱으로 포장하는 도구 (Tauri가 더 가벼움) |
| **MVP** | 최소 기능 제품. 핵심 가치를 보여주는 가장 작은 버전 |
| **로드맵** | 기능을 어떤 순서로 붙일지 정리한 계획표 |
| **DRC → 배치 규칙 검사** | KiCad 설계 규칙 검사를 응용한 가구 배치 자동 경고 기능 |
| **BOM** | 부품(가구) 목록과 수량·가격 집계 |
